# Architecture rules
- Homepage motion uses coordinate-aligned SVG sprites for banner dots, isolated SVG connector endpoint dots, and an extracted magnifying-glass sprite over a glyph-free tile image; route-scoped CSS disables every other animation without changing other pages.
- The collaboration header is a chooser for individual SVU and IBM pages, not a combined page; the retired /collaboration-network URL redirects to SVU (the first partner) to keep old links working, while organisation and programme URLs remain canonical.
- Collaboration carousel slides pair the text panel with BannerStory, which shows the same static client render imported by each organisation's own page and returns nothing when none is approved; hasBannerStory gates the artwork column so a text-only slide spans the full card and carousel/partner-page artwork cannot drift apart.
- The About route renders a data-driven about-overview editorial block with its own compact introduction and existing programme/contact destinations, omitting the shared sidebar and large banner to preserve a coherent full-width reading order.
- Render homepage capabilities from site.ts as eight linked cards at equal 45-degree intervals around a centre circle, with DOM-measured radial connectors meeting card edges; container queries switch to stacked two/one-column grids when the radial canvas cannot fit, preserving readable content.
- Partner enquiry runs in test mode: validate with zod, simulate submission, show success/error, never persist or send. Production delivery will be Exafluence AWS Cloud (not Lovable Cloud); keep endpoint, storage, email routing and env vars configurable via enquiryConfig in PartnerEnquiry.tsx.
- Partner enquiry keeps in-memory answers while rendering only its current step, validating that step before advancing and the full schema before simulated delivery; this preserves answers without exposing completed fields.
- Pages, programmes and hub arms are data in src/data/site.ts; reviewed SVU records live in src/data/svuReviewed.ts and render inline through SvuReviewedContent on the existing catch-all routes, so source-specific records stay separate from navigation and layouts.
- Approved introductory SVU narration and photo associations live in svuOverview.ts, separately from exhaustive reviewed records; overview links target stable original-index project anchors without duplicating research lists or programme brochures.
- SVU career outcomes use source-preserved records in svuCareer.ts and one shared table that becomes record cards on phones, showing each batch as its year range only; the approved internship programme update (svuInternshipUpdate) renders as text only between the introduction and those records, never adding artwork or duplicating a student.
- Programme templates read course-specific data from site.ts through the catch-all route; programmeNavigation.ts supplies canonical organisation/detail paths so carousel, directory, breadcrumbs and back links share one hierarchy; approved brochure access is gated by the existing test-only contact workflow.
- Unconfirmed claims render as "Approved Content Required" placeholders; never invent partnership, placement, ranking or certification content.
- XIME is removed from the network (3 Nov 2026): no XIME page, programmes, slide, logo or enquiry option; its old URLs redirect to /collaboration-network and its renders stay as unused assets.
- Brand-wording checker rules live in src/lib/brandCheck.ts; AI review only via brandCheckConfig.endpoint on Exafluence AWS so the AI key never reaches the browser.
- Website AI features call a project-hosted server function that holds the key; the browser never carries a key. Keep each feature's endpoint override in one config object so the same request can later be repointed to Exafluence-hosted delivery without touching UI code.
- Header menus render primaryNavigation and organisationSections from site.ts, with menu search drawing on menuCategories via navPages, so primary destinations and sidebar-only resources cannot leak into each other's groups; Contact stays accessible through page calls to action.
- Page detail stays on the page itself rather than behind a click: no bottom-anchored panel may cover the viewport, so fuller text renders inline and expandable items (FAQs) open their answer beneath their own question, one at a time.

- SVU renders as three pages (overview+programmes, /outcomes for research, achievements, internships and placements, /faculty) through SvuPages; svuSectionPath maps finer section ids to page anchors and svuLegacyRedirect forwards the retired single-section URLs, so menus and old links keep working.
- IBM keeps one home at /collaboration-network/ibm: narration, SEO, offering facts and enquiry choices live in src/data/ibm.ts and render through IbmPages, while the retired /industry-collaborations/ibm URL redirects there; IBM programme pages end at a section headed "Enquiry" and the institutional form reuses submitTestEnquiry, so it stays test-only.
- The menu bar mark renders as two stacked layers — a nib-free logo plus an absolutely positioned pen-nib sprite sized by the wrapper's fixed aspect ratio — so only the pen moves; keep the wrapper's aspect ratio authoritative so the sprite cannot drift when the artwork loads late.
- Student programme enquiries (StudentEnquiry, ?programme= preselects) and institutional partnership enquiries (PartnerEnquiry, ?type=institution or IBM programmes) are separate forms on /contact, both test-only via submitTestEnquiry, so learners are never asked for organisation details.
- The SVU technologies strip (SvuTechTicker) renders the list twice in a two-column grid and slides the track by exactly one copy, with the repeat aria-hidden and no index numbers or show-all control; reduced motion drops the copy for one static grid, so the loop stays seamless without announcing anything twice.
- SVU faculty render as photo-free cards in one responsive grid (FacultyDirectory); no selection state, no expertise pills.
