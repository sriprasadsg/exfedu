# Architecture rules
- Homepage motion uses coordinate-aligned SVG sprites for banner dots, isolated SVG connector endpoint dots, and an extracted magnifying-glass sprite over a glyph-free tile image; route-scoped CSS disables every other animation without changing other pages.
- The dedicated collaboration-network block renders the shared manual carousel only on its own catch-all page; organisation listings and canonical programme details live beneath /collaboration-network/:organisation, with legacy Academic and /programmes/:slug URLs redirected to avoid duplicate pages.
- Collaboration slides use one data-supplied main artwork image with contain sizing and edge blending; no secondary thumbnail markup, so partner replacements preserve the shared content-panel layout.
- The About route renders a data-driven about-overview editorial block with its own compact introduction and existing programme/contact destinations, omitting the shared sidebar and large banner to preserve a coherent full-width reading order.
- Render homepage capabilities from site.ts as eight linked cards at equal 45-degree intervals around a centre circle, with DOM-measured radial connectors meeting card edges; container queries switch to stacked two/one-column grids when the radial canvas cannot fit, preserving readable content.
- Partner enquiry runs in test mode: validate with zod, simulate submission, show success/error, never persist or send. Production delivery will be Exafluence AWS Cloud (not Lovable Cloud); keep endpoint, storage, email routing and env vars configurable via enquiryConfig in PartnerEnquiry.tsx.
- Partner enquiry keeps in-memory answers while rendering only its current step, validating that step before advancing and the full schema before simulated delivery; this preserves answers without exposing completed fields.
- Pages, programmes and hub arms are data in src/data/site.ts; reviewed SVU records live in src/data/svuReviewed.ts and render inline through SvuReviewedContent on the existing catch-all routes, so source-specific records stay separate from navigation and layouts.
- Programme templates read course-specific data from site.ts through the catch-all route; programmeNavigation.ts supplies canonical organisation/detail paths so carousel, directory, breadcrumbs and back links share one hierarchy; approved brochure access is gated by the existing test-only contact workflow.
- Unconfirmed claims render as "Approved Content Required" placeholders; never invent partnership, placement, ranking or certification content.
- XIME's internal programme overview reads source-verified fields from xime.ts, rendering missing fields as individual review flags without inventing a catalogue entry; its enquiry dialog reuses the test-only contact workflow.
- Brand-wording checker rules live in src/lib/brandCheck.ts; AI review only via brandCheckConfig.endpoint on Exafluence AWS so the AI key never reaches the browser.
- Website AI features call a project-hosted server function that holds the key; the browser never carries a key. Keep each feature's endpoint override in one config object so the same request can later be repointed to Exafluence-hosted delivery without touching UI code.
- Header menus render primaryNavigation, learningEcosystemPages and sidebarPages from site.ts, independently of footer menuCategories, so primary destinations and sidebar-only resources cannot leak into each other's groups; Contact stays accessible through page calls to action.
- Page detail stays on the page itself rather than behind a click: no bottom-anchored panel may cover the viewport, so fuller text renders inline and expandable items (FAQs) open their answer beneath their own question, one at a time.
